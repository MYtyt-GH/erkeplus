## 3. 成绩单页的分类学时（接口已探明）

**背景**：官方 `#/scoreReport` 有精确的学分 / 学时数据。2026-10-29 已抓包实测，
数据源是 `GET student/achievement/detail-app`（无参数），字段表写进
[docs/api](../api/win-9xueqi-api.md) 的「成绩单页」一节。

**已确认**：

- `data.user.hours` / `data.user.score` 就是学时与学分，和排行榜、`my-info` 同一个数
  （实测 3.0 学时 / 0.075 学分，仍是 `hours × 0.025`）
- `data.tags[]` 是**按分类的学时进度**：`name`（分类名）、`minHours`（该分类要求）、
  `userValue`（该分类已得），实测 6 条，`minHours` 为 40 / 5 / 20 / 5 / 40 / 0
- 学时单位走 `dict/school/system-para/list`（`params` 要编码两次），折算规则走 `ways-convert`

**所以数值口径没问题**，原以为的「数据不准」不存在。真正缺的是**分类学时**这个概念：
客户端现在只有一个总学时，没有「哪一类还差多少」。

**要用户拍板**：

- 要不要做「学时分类进度」页（每类一条进度条 + 要求 / 已得）？放「我的」还是「更多」？
- 学号、姓名（`code`、`name`）属于隐私字段，解析了也不展示、不落日志

**状态**：接口已探明，待决定要不要做页面。

## 4. 待办提醒与活动看板（未来）

桌面小组件已在 0.10.0 做了三种（课程看板 / 最近两节课 / 半天课表，见 [docs/design/widget.md](../design/widget.md)），这一条只剩：

- **高度定制的待办**：二课活动（报名截止、签到开始）与上课提醒合在一起，可自定义提前量
- **还没做的两种组件**：活动待办（「我的阅办」的消息数据已经有了，缺活动缓存）、
  活动看板（依赖活动列表落盘）

小组件已单独出设计：[docs/design/widget.md](../design/widget.md)、
[ADR 0006](../decisions/0006-widget.md)。首批做「今日课程」「下一节课」，
活动待办 / 活动看板留到消息与活动缓存落地之后。

为此在课表数据层定下的约定（写进 `docs/design/timetable.md`）：

1. Repository 提供不依赖 UI 的纯查询（`lessonsOn(date)` / `cachedLessonsOn(date)`），
   提醒与小组件直接调用，不拉起界面；
2. 缓存必须能在无网络、无前台进程时同步读出（小组件只读缓存，不发请求）；
3. 课程模型自带 `date`、节次与钟点、教室，够算「还有 10 分钟上课」。

**状态**：设计已出（[docs/design/widget.md](../design/widget.md)），待开工。批次顺序：
「今日课程」→「下一节课」→「活动待办」（消息 M1 已落地）→「活动看板」（依赖活动缓存）。
