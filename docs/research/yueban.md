# 阅办（`#/needDealt`）调查报告

- 调查时间：2026-11-15
- 调查方式：登录会话内的只读请求 + 全量前端源码阅读（`static/js/*`，build stamp 1793948703742）
- 结论：可以完整做成原生页面，第 1 阶段不依赖任何写接口。**待办与消息两半都要做**
  （2026-11-15 用户定：管理员未必不是未来的目标用户，所以不能因为「学生恒为空」就砍掉）

## 一、这个页面到底是什么

官方叫「阅办」，实际上装了两样东西，二者数据源完全不同：

| tab | 内容 | 数据源 | 学生账号 |
| --- | --- | --- | --- |
| 待办 | 需要**我**去处理的事（审核、签到、交作业…） | `activity/processing/statistics` + `activity/processing/list` | 18 个计数**全为 0**，列表为空数组 |
| 已办 | 已处理完的事，**只有组织账号（`identity=2`）能看到这个 tab** | `activity/activity/listByTeacher` | 不出现 |
| 消息 | 系统发给我的通知（学时发放、报名结果、签到提醒、组织动态…） | `message/notice/un-read-count` + `message/notice/list` | 27 条，10 条未读 |

底部导航「阅办」上的红点是**消息未读数**，不是待办数（待办数在页面内「待办」tab 上，>99 显示 `99+`）。

待办 tab 的行是服务端给的四件套 `{icon, workDes, count, route}`，**跳转路径也由服务端给**
（`$router.push({path: e.route})`），所以做起来不难：照 `workDes` 显示、照 `route` 走。
难点在于 `route` 是官方 H5 的路径（如 `/activityAudit/xxx`），我方要逐个映射到自己的页面，
认不出的回退官方网页。学生账号看到的永远是空列表 + 「暂无待办内容~」。

## 二、有没有 WebSocket / 轮询（决定通知怎么做）

结论：**没有 WebSocket，也没有定时轮询**。

| 验法 | 结果 |
| --- | --- |
| 抓 `#/needDealt` 真实网络请求 | 18 个请求全部是 `xmlhttprequest`，没有一个 WS 连接 |
| 5 个 shell bundle 全量 grep | `WebSocket` 0 处、`wss://` 0 处 |
| 415 个按需 chunk 全量下载后 grep | `WebSocket` **0 处**；`setInterval` 有 21 个 chunk 用到，但都与消息无关（轮播、倒计时之类） |

也就是说：**未读数只在你打开页面的那一刻拉一次**，之后放着不动就永远不会变。
没有任何可复用的推送通道——要做系统通知只能自己轮询。

> 更正：本轮调查开始时我先按 `static/js/<id>.<hash>.js` 猜 chunk 地址，415 个全部 404，
> 却因为「文件大于 50 字节」判了成功，差点把「0 处 WebSocket」当成已验证结论写进文档。
> 真实地址是 `static/js/<id>.<hash>.<buildStamp>.js`，build stamp 从首页引用的 `app.*.js` 里取。
> 重扫后结论不变，但**方法上这一步是返工过的**，记在这里。

## 四、做原生页面会踩到的坑

1. **没有 `lastPage`。** 响应只有 `total`/`pageNum`/`pageSize`/`list`。官方 H5 读 `data.lastPage`
   判断「没有更多」，永远读到 undefined，所以它只能一直翻到空列表为止。我们按
   `pageNum * pageSize >= total` 自己算，少发一次空请求。
2. **`dynamic/unread/count` 返回字符串**，`"0"`；`message/notice/un-read-count` 返回整数。
   同一个字段名两种类型，解析时分开写。
3. **`showDelete` 是字符串 `"false"`**，不是布尔。目前样本全是 `"false"`，语义未验证，
   不要拿它当「能不能删」的开关用（官方自己的单条删除入口在列表项组件里，与这个字段无关）。
4. **删除与清空是同一个接口**（`notice/clean`），靠 `id` 是否为空区分。别去找
   `message/delete`，那是另一个页面的东西。
5. **点开即已读。** 只要 `isRead==0`，点击就发 `notice/read`，成功后才重拉列表。
   我方如果 skip 这一步，未读数会永远对不上。
6. **`managerId == 我` 的消息走管理员视角。** 同一条「开始签到」通知，管理员点进去是
   带审核/管理按钮的活动页，学生点进去是只读活动页。我方只做学生视角，遇到
   `managerId == 我的 userId` 时按学生页处理（或直接跳官方），不要试图猜管理员页。
7. **`type=162`（黑名单通知）点了不跳转**，只标已读。这类只能列表里看正文。

## 五、与「我的」页的关系

用户决定：**入口放「我的」页，名字叫「我的消息」**（符合「我的 X」命名规则）。
一个入口，进去就是官方那个「阅办」页：上方 tab 待办 / 消息（组织账号再加一个已办），默认停在待办。

于是「我的」页会是：我的信息（资料卡）/ 我的诚信值 / 我的组织 / **我的消息** / 我的附件 / 我的课表。
学分那张数字卡仍然点得进成绩排行榜，但「学分排行榜」这个**条目**在「更多」页（2026-11-15 用户定）。

未读数怎么显示：用户采纳「第一版不加角标」——加了就得为它单独轮询，等 M3 有了轮询再顺带显示。

## 六、范围（2026-11-15 用户审核确定）

| 阶段 | 内容 | 依赖 |
| --- | --- | --- |
| M1 | 消息列表页：分页、下拉刷新、未读/已读样式、「N 条未读通知」一键全读 | 只读接口 + `read-all` |
| M2 | 点开消息：自动标已读 + 按落点跳活动/组织详情，认不出的回退官方页面 | `notice/read` |
| M3 | 待办 tab：`processing/list` 的 `{icon, workDes, count, route}` 列表 + 空状态；`route` 能映射的映射、映射不上的回退官方页面 | 只读接口 |
| M4 | 系统通知：`WorkManager` 轮询（≥15 分钟）+ 本地去重 + 通知渠道 | 只读接口 |
| M5 | 设置：开关与间隔、免打扰 | — |

**待办 tab 排在通知之后**：它对现在的用户恒为空，做了也看不到内容，但结构简单（列表 + 空状态），
等有组织账号用户时立刻有用。已办 tab 仅组织账号可见，暂不做（无样本、无页面）。

明确**不做**的：管理员视角消息、清空与单条删除（写操作，对用户无价值）。
消息列表也**不做**按类型分组/筛选——官方没有筛选，只有时间倒序。
