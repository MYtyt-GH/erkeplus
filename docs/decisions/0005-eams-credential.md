# 0005 教务课表凭据：默认不落盘，可选只存 token

- 状态：已采纳
- 日期：2026-11-15

## 背景

课表来自新教务系统 `jwglyd`（见 [docs/api/eams-jwglyd.md](../api/eams-jwglyd.md)），
它用的是**学校统一身份账号密码**，和二课的账号是两套。登录后拿到 `token` + `secret`，
之后每次请求都要用这两个值签名。

用户 2026-11-15 定下两种用法，都要支持：

1. 图省事的用户：**只用一次，用完就丢掉**，明确告知使用范围；
2. 愿意记住的用户：可以存在手机上，之后每次进课表自动拉最新的。

两种用户都要有**本地缓存保底**：能实时拿到就用最新的，拿不到就用缓存的课表。

## 决策

1. **默认「用完即弃」**：密码只活在登录弹窗与内存里，登录成功后立刻丢弃；
   不落盘、不进日志、不进崩溃上报。本次运行内可以复用 `token`，进程结束即失效。
2. **可选「记住」只存 `token` + `secret`，不存密码**：复用 ADR 0002 已经建立的
   Keystore AES-256/GCM 加密（同一个密钥体系，不新造一套），存进 SharedPreferences。
   关闭记住或点「清除课表凭据」时删除。
3. **不存密码换取可自动重登**：不做。token 一旦过期，提示用户重新输入一次。
4. **登录用弹窗表单**，不单开页面：两个输入框 + 一个「记住」勾选 + 一句范围说明。
   官方现在 `enable:false`（无验证码），将来若开启，在同一个弹窗里加一行验证码。
5. 弹窗里必须写明范围：**只用于查询课表，不会上传到任何第三方服务器**。

## 理由

- 教务账号 = 学校统一身份，比二课 token 敏感得多：教务接口能读学籍，里面有身份证号、
  手机号。一旦落盘等于把「账号本身」放进手机，风险与收益不成比例。
- 存 token 不存密码：手机丢失或被备份导出时，攻击者拿到的是一个会过期的会话凭证，
  不是可以长期使用的密码。代价是过期要重输一次，我们认为值得。
- 复用 0002 的 Keystore 机制，避免项目里出现两套加密实现、两种解密失败处理。
- 弹窗而不是独立页：只有一个表单，做成页面会多一次跳转、多一个返回栈节点，
  而且「用完即弃」模式下用户每次都可能要面对它。

## 被排除的选项

| 选项 | 为什么不做 |
| --- | --- |
| 存密码、过期自动重登 | 体验最好，但泄露即账号丢失；教务密码还能进统一身份的其他系统 |
| WebView 登录 + cookie 持久化 | 官方 H5 是手机浏览器排版，嵌进来体验差；cookie 生命周期不可控，登出与清理都要额外处理 |
| 明文 SharedPreferences 存 token | 不可接受 |
| 云端代持凭据 | 用户已否决服务器方案（同 IP 集中轮询易被判异常、无法保证不泄露） |
| 每次都要输密码（连 token 都不留） | 「记住」模式下每次进课表都输密码，实际没人用 |

## 后果

- **token 有效期未知**（待真机验证）。若只有几小时，记住模式的价值会打折，
  届时要重新评估是否允许存密码（那将是一次新的 ADR，不是偷偷改实现）。
- 首次进入课表必须弹登录表单；弹窗要能取消，取消后停留在缓存视图 + 一个「更新」按钮。
- 卸载、清数据、切换账号都要清掉加密的 token。
- 课表页需要一个「清除课表凭据」的入口，否则用户没有反悔的途径。
