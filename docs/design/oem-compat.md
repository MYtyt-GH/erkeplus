# 国内厂商系统（魔改 Android）兼容策略

目标：**以最低成本兼容**。不做逐机型适配、不做特殊权限引导、不承诺后台准时。
课表、消息这些「用户主动打开才看」的功能，本来就不依赖后台能力，这一类零成本。

## 一、按「能力 → 被谁限制」盘点

| 能力 | 谁会对它下手 | 我们的选择 |
| --- | --- | --- |
| 前台页面、网络请求 | 不限制 | **放心用**：课表页、消息页、登录弹窗都只在前台跑 |
| 应用私有目录读写 | 分区存储不影响私有目录 | 放心用：课表缓存写在 `filesDir/timetable` |
| `WorkManager` 周期任务 | MIUI / EMUI / ColorOS 等会延迟、合并、甚至在省电模式下不跑 | 只做「尽力而为」，界面上说「定期检查」，不说「准时提醒」 |
| `AlarmManager` 精确闹钟 | Android 12+ 需要 `SCHEDULE_EXACT_ALARM` 用户授权；OEM 还会杀 | **首版不用**。上课提醒若要做，也先用 WorkManager 的近似时间 |
| 通知 | Android 13+ 需要 `POST_NOTIFICATIONS` 运行时权限；OEM 会默认压低渠道重要度 | 第一次打开开关时申请；被拒就置灰说明，**不做二次骚扰** |
| 自启动 / 后台弹窗白名单 | 需要用户手动在系统设置里开，各家入口都不一样，教程维护成本极高 | **不引导**。宁可少提醒，也不给用户一份三天就过时的教程 |
| 电池优化白名单 | 同上，且申请理由难向用户解释 | **不申请** |
| 前台服务常驻 | Android 14+ 要求声明 `foregroundServiceType` 且要有正当理由 | **不做常驻服务** |
| 桌面小组件 | 系统把 `updatePeriodMillis` 下限卡在 30 分钟，且不保证准点 | 只显示缓存，**数据变了主动推一次**，不靠系统定时刷新 |
| WebView 内嵌官方页 | 各家 WebView 内核版本差异、cookie 行为差异 | 只作为「打开官方页面」的兜底，不做核心功能 |

## 二、最低成本的三条落地规则

1. **前台做对**：进入课表/消息页就刷新一次，失败用缓存 + 明确的时间戳提示。
   用户看到的永远是最新（或明确标注的旧）数据，不依赖任何后台能力。
2. **后台只做 WorkManager**：周期下限 15 分钟，实际可能几小时才跑一次。
   文案统一写「定期检查」，不写「准时提醒」；设置页里写明「部分机型会延迟」。
3. **一个特殊权限都不申请**：自启动、电池优化、精确闹钟、悬浮窗，全部不碰。
   少一个权限就少一类「为什么它要这个」。将来真需要，再单独写一次 ADR。

## 三、按 API 级别分支（minSdk 26 / targetSdk 36）

只按系统版本分支，不按厂商分支：

| 能力 | 起始 API | 处理 |
| --- | --- | --- |
| `POST_NOTIFICATIONS` | 33 | 运行时申请；32 及以下直接可用 |
| 通知渠道重要度 | 26 | 建渠道时给 `DEFAULT`，由用户决定是否升到横幅 |
| `SCHEDULE_EXACT_ALARM` | 31 | 不使用（见上） |
| 前台服务类型 | 34 | 不使用（见上） |
| 移动网络/流量提示 | 26 | 不涉及：全部是小 JSON |

厂商差异只体现在**后台执行时机**与**通知展示形态**，这两项我们都不承诺，所以不需要机型分支。

## 四、验证方式

- 主验机型：24090RA29C（Android 16），本项目一直用这台。
- 不追求覆盖其它 ROM；如果用户反馈某机型课表打不开，先怀疑网络与教务可达性，
  再怀疑缓存权限，**不要**一上来就归因于「国产系统杀后台」。
- 后台能力（轮询、小组件）上线后，验收标准是「有机会收到」而不是「一定准时收到」。
