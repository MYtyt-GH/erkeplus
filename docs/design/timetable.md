# 我的课表（教务课表）

数据来自新教务 `jwglyd`（不是 `jwgl` 网页版），接口见 [docs/api/eams-jwglyd.md](../api/eams-jwglyd.md)。
入口：「我的」→「我的课表」（已有占位，见 [organization.md](organization.md) 的分工规则）。
凭据怎么存见 [ADR 0005](../decisions/0005-eams-credential.md)。

## 为什么不用 WebView 嵌教务

教务有现成 H5（`https://jwglyd.aust.edu.cn/app-web/`），但它是**给手机浏览器排的**：
字号、点击区、周表格都不适合原生层复用，且嵌进去要处理 cookie 持久化、校外网络、登录态过期后
跳转一堆官方页面。我们已经有干净的 JSON 接口 + 签名算法（实测通过），做原生页更轻。

## 两种凭据模式（用户 2026-11-15 定）

| 模式 | 密码 | 存什么 | 行为 |
| --- | --- | --- | --- |
| **用完即弃**（默认） | 只在表单和内存里活一次，登录成功立刻丢 | 什么都不存 | 本次运行内复用 token；重进 App 要再输一次 |
| **记住（可选）** | **不存** | `token` + `secret`，用 Android Keystore 加密 | 每次进课表都自动拉最新；token 失效时提示重新输入 |

关键取舍：**两种模式都不把密码落盘**。愿意记住的用户存的是 token，不是密码——
代价是 token 过期后要再输一次密码；收益是手机丢了也拿不到教务密码。

表单里用一句话写明范围：「只用于查询课表，凭据不会上传到任何第三方服务器」。

## 登录表单（一个弹窗，不单开页面）

```
┌ 登录教务 ─────────────────────┐
│ 账号  [____________]           │  ← 学号
│ 密码  [____________] 👁        │  ← 可切换明文，避免输错
│ 初始密码可能是身份证号后六位     │  ← 用户提示，减少白发问
│ ☑ 记住，下次不用再输            │
│ 只用于查询课表，不会上传到第三方  │
│ [取消]            [登录]       │
└───────────────────────────────┘
```

- 两个输入框就够：当前 `/verify-code` 返回 `enable:false`，**没有验证码**。
- 若将来 `enable=true`：同一个弹窗里加一行图形验证码 + 输入框，调 `/login-with-verify-code`，
  不新开页面。`imageArray` 的格式尚未见过，到时按真实样本做。
- 失败文案按错误码分：「账号或密码不对」/「请求太频繁，请稍后再试」/「教务系统连不上」。

## 页面结构

```
[返回] 我的课表                            [更新]
第 11 周 · 2026-2027 第 1 学期      更新于 05:12
  ‹      第 11 周 · 本周                  ›
          今天 3 节课 · 08:00 数学分析(一)
┌────┬──────────┬──────────┬──────────┬──   ← 只有课表横向滑
│节次│  一 9    │  二 10   │  三 11   │ …
│ 1  │ 课程名    │          │          │
│08:00│ 明理北楼 │          │          │
│    │ 明理北103│          │          │
│ …  │ 12 节，一屏装满，不上下滚          │
└────┴──────────┴──────────┴──────────┘
左右滑动看整周 · 点课程看教师与教室      [退出教务登录]
```

- **整页不上下滚动**：上半是固定信息区（标题、周次与今日摘要、提示），下半由课表占满。
  2026-11-15 用户反馈「课表太大」，改成这个结构后 12 节一定一屏装得下。
- **只有课表横向滑**：每列 116dp，一屏约 3 天。左侧固定「节次 + 上课时间」，
  右侧「表头 + 网格」共用一个横向滚动状态，列始终对齐。
- **作息表**（用户 2026-11-15 提供）写死在 `LESSON_SLOTS`：
  1 08:00-08:45、2 08:55-09:40、3 10:00-10:45、4 10:55-11:40、5 14:00-14:45、6 14:55-15:40、
  7 16:00-16:45、8 16:55-17:40、9 17:50-18:35、10 18:45-19:30、11 19:40-20:25、12 20:35-21:20。
  左侧只显示开始时间，完整起止在点开课程的小卡片里。
- **课程块三行**：课程名（12sp）、楼栋（10sp）、房间号（10sp）。楼栋与房间分开显示——
  一个带编号（明理北103）、一个不带（明理北楼），这是用户明确要求的信息层次。合班多教室时补「等 N 处」。
- 周末两天也在 7 列里；今天那一列用主色浅底块区分。
- 「成绩查询」「考试安排」不在这页——它们不属于一张周课表，入口在「更多 → 教务」（敬请期待）。

## 缓存与刷新（用户要求：两种用户都有缓存保底）

- 每次拉成功都落盘：`semester_id` + 该周课程 + `fetchedAt`。按「学期 + 周」分片存；
  **学期本身也缓存**（`semester.json`）——离线时没有它就算不出周次，课程缓存等于白存。
- 进页面：**先渲染缓存**（学期与课程都从缓存来，所以没登录、没网络也能看），
  再按模式决定是否自动拉：
  - 记住模式：自动拉一次最新；
  - 用完即弃模式 / 已清除凭据：只显示缓存，顶部写「未登录教务：下面是本地缓存的课表」。
- 「更新」按钮三种行为：有 token 直接拉；token 失效弹登录表单；没有 token 就弹表单。
- 拉失败（校外、断网、教务抽风）：保留缓存，顶部出现一条浅色提示
  「暂时连不上教务，显示的是 11-15 03:12 的课表」。**绝不把空结果写进缓存**。
- **清除登录凭据 ≠ 清除课表**：清掉的只是教务 token，缓存课表留着，离线照样能看。

## 数据层（为将来的待办提醒与小组件留口）

```
EamsClient      // 签名、POST、base64 拆信封；只管协议
EamsRepository  // semesters(学期列表) / lessonsOfWeek(semesterId, weekStart) / currentWeek()
```

约定，写进代码注释里：

1. **不依赖 Compose / Android 上下文就能查**：`lessonsOn(date)` 这类纯函数放 Repository，
   将来 WorkManager 的「上课提醒」和桌面小组件直接调用，不需要拉起 UI。
2. **缓存读是同步可用的**：小组件进程里没有网络就跑不起来，所以它只读缓存；
   Repository 要提供 `cachedLessonsOn(date)` 这种不抛异常的读法。
3. 课程模型带 `date`、`start_unit/end_unit`、`start_time/end_time`、`room`、`teacher`，
   够「还有 10 分钟上课」这类提醒用，不需要再回查接口。

## 国内厂商系统（魔改 ROM）

课表页**完全在前台工作**：进入就请求、失败用缓存 + 时间戳提示。所以它不依赖任何会被 OEM
限制的后台能力，兼容成本为零。

将来接后台（定时刷新、上课提醒、桌面小组件）时按 [oem-compat.md](oem-compat.md) 的规则：
只用 `WorkManager`、不申请自启动/电池优化/精确闹钟这类特殊权限、文案只说「定期检查」不完诺准时。

## 不做（首版）

- 成绩查询、考试安排：只留「敬请期待」入口（接口已探到，见 backlog）
- 未排课（实验课、线上课）：`get-unscheduled-lessons` 参数未定，先不做
- 多学期课表切换：默认当前学期，跨学期只在周次切换越界时自动跟上
- 课程详情页、教学任务页（官方那套长尾页面）

## 待验证

- 真实登录一次（密码错误码、token 有效期）；token 过期后的表现决定「记住模式」的可用性
- 周表格在 360dp 窄屏上的可读性（7 列 × 12 节是否要改成 5 天 / 6 天可切）
- 教务接口频控阈值（保守实现：请求间隔 ≥1s，失败指数退避）
